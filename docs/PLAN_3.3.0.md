GlyphWorks 3.3.0 implementation plan

Status: approved implementation complete; automated validation passed (2026-09-11).
Phone (4a) Pro Android integration checks passed; physical-panel observations and
remaining hardware coverage are recorded below.

Accepted refinements during implementation:

- Notifications shows 0–9 and then 9+, rather than multi-digit counts. The backend
  retains the exact count; both panel renderers apply the same compact display.
- Device-free artwork and replayable previews are generated by the JVM tests
  alongside their ASCII goldens. No separate preview/helper tool is added.
- The 13×13 artwork was established and reviewed before Android backend work.
- Notifications offers a large envelope, lowercase “txt” (default), notification
  dot, and full-size bell/count marquee. One preference controls standalone and
  Ambient rendering. Temperature is above the °C/°F label. JVM goldens cover both
  panels, negative temperatures, and marquee transitions.
- Ambient uses the individual toys' settings. Schema 4 discards the duplicated
  Ambient charging style and preserves Battery's gauge/wattage choice; the same
  Battery renderer serves its toy, Ambient charging, and the Battery background.
- Initial setup includes direct access to Weather opt-in and both location grants;
  Settings keeps notification access and Weather setup available before either is
  enabled. A new Ambient tutorial explains the cycle and links to its settings.
- Weather remains an explicit opt-in. Background approximate-location access lets
  it follow movement while locked; foreground-only access still allows weather
  refreshes for the last location while locked.

Baseline checked: 22 existing JVM tests passed, with zero failures/errors, covering
Ambient, its sky-renderer delegation, Solar/Moon goldens, the brightness audit at
both sizes, and GlyphCanvas panel geometry. Run in comparison mode; existing
goldens and application source were not changed.

Scope: GlyphMatrixToyCompat only. Develop dynamic Ambient backgrounds and two new
information toys, Notifications and Weather, for both supported phones and both
distribution flavors. The user confirmed that GlyphWorks is permanently
noncommercial, has no preferred weather provider, and expects weather to follow
location changes while the phone is locked.

1. Establish the artwork using the existing device-free test workflow.

   Use `TestHarness`, `FakeClock`, `FakeScheduler`, and `GoldenAscii`, following the
   existing clock, sky, game, and Ambient tests. Begin with Phone (4a) Pro's 13×13
   panel, then create Phone (3)'s 25×25 variants. Both designs must work within the
   existing `PanelMask`, whose geometry is already tested for 137 and 489 LEDs.

   Design Notifications with an envelope above a legible count. Cover zero,
   one through nine, 9+ overflow, and unavailable access as distinct states.
   Design Weather with recognizable clear-day, clear-night,
   partly cloudy, overcast, fog, rain/drizzle, snow, and thunderstorm icons, plus
   temperature, loading, and unavailable states. Cover negative temperatures,
   zero, and three-digit Fahrenheit temperatures.

   The proposed weather loop is: hold the centered icon for 3 seconds; slide it
   left while temperature enters from the right over about 1 second; hold the
   temperature for 3 seconds; slide left again to the returning icon. Restart
   at the icon when Weather becomes visible. Final pixel positions and compact
   unit layout are established through the 13×13 goldens before the 25×25 work.

   Store key animation frames as ASCII goldens and test the timeline with fake
   time. Generate enlarged panel previews and a replayable animation directly
   in the JVM tests from these same rendered frames, using the tested `PanelMask`
   for geometry. `GoldenAscii` compares square buffers, so the tests also assert
   mask clipping and the previews show only physically present cells.

   Review the new goldens deliberately; update only their targeted tests, then
   run them again in comparison mode. Physical hardware is not required for
   this design phase.

2. Make Ambient's background a selectable cycle.

   Replace the radio group with individual on/off rows for the existing ten
   backgrounds and the two new ones. Cycle in the order displayed in the list.
   Keep these selections independent of the main Glyph Toys enabled list.

   Add a stable-ID selection preference and an idempotent migration from the
   current numeric `ambientBackground` preference. Existing users retain their
   one selected background. Fresh installs retain the digital-clock default.
   Add a “Change automatically every 15 seconds” switch, off by default.

   Handle `Events.CHANGE` in Ambient so one Essential Key press advances through
   enabled backgrounds and wraps. Use the same event path for Phone (3)'s Glyph
   Button. Reset the 15-second interval after manual changes. Keep double/triple
   presses and menu navigation working through the existing router.

   Retain the current priority: music, then charging, then background. A manual
   press changes the selected background even while an overlay covers it; it
   becomes visible when the overlay ends. Pause automatic cycling while an
   overlay or night/shake gating hides the background, and give the background
   a fresh interval when it returns. Retain the selected background across
   in-process toy switches; start from the first enabled background after a
   process restart. Use elapsed time for intervals, independent of wall-clock
   changes, and avoid rapid catch-up cycling after a long suspension.

   One enabled background stays fixed. An intentionally empty selection leaves
   the background blank while charging/music still operate. Apply selection
   changes live and recover deterministically if the current entry is removed.
   Give animated/data backgrounds explicit visibility lifecycle handling.

3. Add the Notifications data source and standalone toy.

   Add an Android `NotificationListenerService`, manifest declaration, access
   status, and system-settings entry point. This is separate from the existing
   `POST_NOTIFICATIONS` permission used to post GlyphWorks' own notifications.

   Android exposes outstanding notifications, not reliable per-app message-read
   state. Define the count as active dismissible notifications. Exclude ongoing
   service/media entries and avoid counting both group summaries and children;
   count a summary once if it is the only representation of its group. Opening
   the shade alone does not clear the count. Explain these semantics in settings.

   Seed state on listener connection, update by notification key on posts and
   removals, and rebuild after reconnection. Represent unavailable access
   separately from a real zero. Keep only the metadata needed for counting in
   memory; do not retain or transmit notification text or modify notifications.

   Expose a platform-independent notification snapshot port. The standalone
   toy and Ambient background share one renderer and one data source.

4. Add Weather data, location updates, and the standalone toy.

   Use Open-Meteo's current conditions endpoint over HTTPS for temperature,
   weather code, and day/night state. Include provider attribution and a Celsius
   / Fahrenheit setting shared between standalone Weather and Ambient.

   Add a testable weather repository and read-only snapshot port. Run location,
   network, parsing, and cache I/O outside the compositor thread. Refresh weather
   about every 15 minutes while needed, and after meaningful location changes,
   with request deduplication, timeouts, bounded response handling, and backoff.
   Use a recent cached observation when offline; distinguish stale data and
   show an unavailable state after a defined expiry (proposed: 2 hours).

   Obtain a recent approximate location and continue low-frequency location
   updates while Weather is in use, including while locked. Request coarse
   location first, then explain and link to Android's separate background
   location grant. If the user grants only foreground access, refresh location
   when the app is visible and show weather for that last location in the AOD.
   Handle disabled location, missing fixes, revocation, and movement explicitly.
   Android may defer background work in deep idle; cached frames remain usable.

   Start weather activity only after Weather is configured and used, including
   selection in the Ambient cycle. Suspend unnecessary location/network work
   when it is no longer needed. Keep weather/location cache in app-private
   credential-protected storage, excluded from backup and guarded before first
   unlock. Preserve the existing protection against pre-unlock Glyph service
   startup. Clear or invalidate relevant cached state when access is revoked.

5. Integrate settings, both flavors, and release metadata.

   Register both new toys in `ScreenRegistry`, `ScreenNames`, the default toy
   order, and settings-dialog dispatch. Reuse each renderer from Ambient,
   following the existing Battery/Solar/Moon pattern. In this checkout,
   Connection status itself is only an Ambient background.

   Add contextual setup/status controls in the new toy settings and Ambient,
   and update onboarding and the setup checklist. Distinguish notification
   access from permission to post notifications. Ensure permission status
   refreshes when returning from Android Settings. Use existing controls in
   both the standard and Lucent themes.

   Weather ships in both `github` and `play`, so move `INTERNET` into the common
   manifest. Keep the assistant and updater excluded from Play. Update manifest
   comments, build documentation, accessibility disclosure text, README, toy
   documentation, and privacy policy that currently claim Play cannot network
   or that location never leaves the phone. Document the approximate location
   sent to Open-Meteo, its attribution, background access, and local notification
   counting. Prepare notes for the corresponding Play listing declarations.

   Set `versionName` to `3.3.0` and increment the current `versionCode` from 20 to
   21. Prepare the build artifacts and change summary for review.

6. Validate behavior and delivery.

   Extend existing JVM tests and fakes for: migration from old/current prefs;
   empty/single/multiple selections; manual wraparound; the 15-second boundary;
   timer reset; hidden backgrounds; overlay precedence; live edits; toy switches;
   and Essential Key versus Glyph Button routing, including menu mode.

   Add notification tests for duplicate updates, removals, grouping, persistent
   entries, reconnects, zero, and denied access. Add weather tests using fixed
   provider responses for code mapping, units, malformed/missing data, timeout,
   rate limiting, cache expiry, location changes/revocation, and marquee phases.
   Verify shared rendering in standalone and Ambient modes at both sizes,
   frame bounds/brightness, and visibility lifecycle behavior.

   Run both flavors' unit suites, debug builds, lint, and release compilation
   with R8. Inspect merged manifests for the new permissions/components and
   confirm that Play still excludes assistant/updater code.

   Then use the Phone (4a) Pro for permission flows, real notification updates,
   locked/AOD cycling, charging/music transitions, weather refresh/location
   behavior, and process restart/reboot checks. Ask the user to connect it at
   that point. Phone (3) gets full device-free rendering/event coverage; report
   physical-device coverage accurately if that phone is unavailable.

Validation record (2026-09-11):

- Both complete debug JVM suites pass: GitHub 658 tests, Play 434 tests, with no
  failures, errors, or skipped tests. New ASCII goldens were generated only through
  `InformationScreensTest`, visually reviewed for 13×13 and 25×25, and compared
  again without update mode. Every notification digit and 9+ is represented.
  All four notification styles have both-panel goldens, including bell transitions.
  Shared-style tests cover live edits/counts, visibility resets, and monotonic time.
  Battery parity and schema 4 migration tests preserve true, false, and absent
  standalone settings while discarding every legacy Ambient charging style.
- Final artwork goldens include both partly cloudy night variants, the lowered
  large-envelope count, the hand-tuned FroggerPro crescent, and Metroid's native
  crescent. Regression checks cover complete notification glyphs, opaque cloud
  overlays, and the one-pixel cloud/lightning gap on both panels.
- Both debug APKs, both release APKs, and the Play release AAB compile, including
  release R8 optimization. Release artifacts are unsigned because this checkout
  has no release signing setup.
- Both debug lint runs report zero errors (GitHub 47 warnings, Play 33 warnings).
  The warnings introduced in the new notification/settings code were corrected.
- Merged debug/release manifests contain coarse/background location, Internet,
  and the protected notification listener; no fine location is requested. Release
  mappings retain Weather and the notification listener. Play contains no
  assistant or updater classes/components. All variants report 3.3.0 / code 21.
- A live Open-Meteo request using synthetic coordinates confirmed the expected
  response format. Repository/HTTP failure tests use fixed local responses.
- Source/documentation diff checks pass; ASCII goldens retain their intentional
  fixed-width spaces. No extra preview tool was added under `art`.
- Device integration was tested on FroggerPro (A069P, Android 16 / API 36), never
  the connected Vivo. The installed 3.2.0 Play app has a release signature, so a
  separate `space.linuxct.glyphworks.dev` / “GlyphWorks Test” Play debug build
  exercised the same 3.3.0 code without replacing that installation or its data.
  The temporary application ID and label overrides live outside the source tree.
- Onboarding exposes the separate notification-access disclosure and a working
  “Set up Weather” entry. Settings exposes both setup entries; the Ambient
  tutorial renders all six steps and opens Ambient settings from its final step.
- Notifications and Weather both activate from the main toy list. The Android
  notification listener, Accessibility service, and Nothing AOD toy service bind.
  Revoking/regranting notification access updates the settings status and restores
  the listener. No personal notifications were dismissed for testing.
- The follow-up styles build was installed on FroggerPro. All four notification
  radio choices persisted through the UI. Ambient shows the shared-settings
  explanation and opens the individual Battery dialog through its new link.
  Device migration changed schema 3 to 4, removed the old Ambient style value 4,
  and preserved the absent/default Battery preference plus all Ambient selections.
  Bell was selected in that test build for physical review; its new animation/artwork
  has JVM/golden coverage, without claiming a user-confirmed rear-panel review yet.
- Weather returns live data on the device. Disabling it deletes its private
  cache; enabling it retrieves fresh data. The background-location settings route
  works: changing “Allow all the time” to foreground-only updates the setup badge
  and explanation, and restoring the grant restores the granted status. Android
  restarted the test process after the downgrade; settings and services recovered.
  Low-power coarse location requests use a 15-minute interval and 5 km movement
  threshold; Android delivered real fixes. A subsequent periodic fetch advanced
  the cached observation without a manual refresh.
- Ambient persists multiple backgrounds and the automatic-cycle toggle. The
  device entered Dozing with Ambient active and the Nothing AOD service bound.
  The user observed the rear display and confirmed all three physical checks:
  backgrounds cycle roughly every 15 seconds, Weather slides left between its
  icon and temperature, and an Essential Key press advances the background.
  Controlled notification-count changes, charging/music transitions, travel,
  sustained deep idle, and reboot remain separate hardware checks. Phone (3)
  coverage is device-free.
- Temporary keep-awake and TCP ADB changes were restored: keep-awake is off,
  the original 30-second screen timeout remains, and ADB is back in USB mode
  (`service.adb.tcp.port=0`) with no forwarding left behind. At the end of device
  validation, the notification/background-location grants were restored and
  Ambient was configured for clock, battery gauge, notifications, and weather
  at 15-second intervals. Charging display was disabled so USB power did not
  cover the backgrounds. The user subsequently removed the separate test app.
  Later artwork revisions were reviewed through JVM goldens and local PNGs,
  with no further device testing or installation.
